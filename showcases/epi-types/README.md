# ePI Types 1–4 showcases

Eleven interactive showcases of the HL7 FHIR ePI types. Types 1, 3 and 4 use one synthetic product, **Sakura Bloom 20 mg film-coated tablets**. Type 2 uses **WonderDrug 250 mg/5 mL powder for oral suspension**, adapted from the HL7 ePI IG example, to show the manufactured item (the powder) and the administrable product (the suspension).
The overview page is `showcases-epi-types.html` at the site root.

`viewer.html` is the ePI viewer: the full SmPC, package leaflet and instructions for use, with tabs for Types 1–4.
Type 2 adds product chips and a product data column, Type 3 adds clinical chips and a clinical data column, Type 4 highlights
the linked phrases (textLink) and shows the data behind a selected phrase. Everything is rendered from `data/epi-data.js`.
Fragment: `viewer.html#t=3&doc=pil`.

| Page | Showcases |
|---|---|
| `type1.html` Digital label | Reader (each document as one continuous page, with contents and search) · Intake validation (Type 1 rules, simulated conversion mistakes) |
| `type2.html` Product identification | Product passport (three phone screens: the pack and its contents, before you mix and after you mix, ingredients, company and authorisation) · Spec sheet (as supplied vs as taken, attribute by attribute, with ingredient strengths in both forms) |
| `type3.html` Clinical information | Clinical particulars as data (ClinicalUseDefinitions) · Patient safety check (personas, dose cap from data) · Undesirable effects from data (4.8 table and leaflet checked) |
| `type4.html` Dynamic digital label | Linked reading (textLink) · Personalised leaflet (lens on the approved text) · One change, every document (safety update regenerates the SmPC and the leaflet) · Link integrity |

Each view has its own URL fragment, for example `type4.html#read/pil-en/pil-2`.

## Synthetic data only

- Sakura Bloom and Sakuramil are fictitious (ICH M4Q(R2) mock-up). The mock-up has no clinical content.
- Every sentence of the SmPC, the leaflet and the IFU is written in `build/content.py` for this showcase. The indication, dosing, contraindications, interactions, pharmacology and undesirable effects are invented. No text is taken from a real product label.
- Product, tablet, ingredient, substance and organisation resources are reused from `sakura-bloom-r2/fhir/resources` (PQI). Pack sizes, GTINs (GS1 restricted-circulation prefix 02), MA numbers and the MAH are invented.
- Type 2 values (WonderDrug suspension) follow the IG's illustrative, non-authorised example. The IG bundle has no SubstanceDefinition; the ones here add names, UNII identifiers and molecular formulas. Ingredient functions and per-bottle sucrose and sodium benzoate amounts are derived.
- Every resource carries the `HTEST` security label.

## Coding notes

- SmPC headings: EMA SPOR codes (`https://spor.ema.europa.eu/rmswi`), as in the IG's WonderDrug examples. Document types: SPOR 100000155532 (SmPC) and 100000155538 (Package Leaflet).
- Leaflet and IFU headings use local example code systems (`pil-0`…`pil-6`, `ifu-0`…`ifu-7`) because verified codes for them were not available. The IFU's document type is `instructions-for-use` from the IG's example code system; its six step pictograms are contained Binaries drawn for this showcase.
- Conditions use SNOMED CT, medicines ATC, dose forms EDQM. A few concepts (breast-feeding, galactose intolerance, ALT increased, eGFR, age) use local example codes.
- Type 4 puts one `textLink` per linked phrase on `section.text`, as the ePI Composition profile allows. The core extension allows one per element, so validators will flag this until FHIR-59812 is resolved.
- The bundles have not been run through the HL7 FHIR validator.

## Files

- `type1.html` … `type4.html`, `epi-types.js`, `epi-types.css`: the pages and the shared shell. Styling builds on `../pqi-types/pqi-types.css`.
- `fhir/Bundle-epi-t{1..4}-{smpc-en,pil-en,ifu-en}.json`: the 12 FHIR R5 document bundles (generated).
- `fhir/Bundle-wonderdrug-suspension-product.json` and `data/wonderdrug-suspension.js`: the Type 2 product resources (generated by `build/build_wonderdrug.py`).
- `data/epi-data.js`: the same bundles for the pages (generated). Do not edit by hand.
- `build/content.py`: the authored text, with link markup. `build/build_epi_types.py`: the generator.

## Rebuild

```bash
python3 showcases/epi-types/build/build_epi_types.py
python3 showcases/epi-types/build/build_wonderdrug.py
```

The output is deterministic. The build fails if any reference or textLink does not resolve inside its own bundle, or if any narrative is not well-formed XHTML.
The SmPC 4.8 table and leaflet side-effect lists are generated from the undesirable-effect resources by `ue_table` / `pil_se`; `EP.ueTable` / `EP.pilSideEffects` in `epi-types.js` must produce the same output (Type 4 showcase 3 checks this).
